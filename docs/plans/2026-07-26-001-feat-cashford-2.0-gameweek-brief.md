## 1. Decisions made

| # | Question | Decision | Implication |
|---|----------|----------|-------------|
| 1 | Money model | **Fixed ante per gameweek pot.** Every entrant stakes the league's ante into the GW pot; top points takes it. | New money semantics beside the per-match engine: entry record per member per GW, pot total, payout as `transfers` rows so Dues/ledger stay untouched. |
| 2 | Deadline | **One GW deadline, FPL-style.** All picks lock at FPL `deadline_time` (90 min before first kickoff). Read it from the API, never compute it. | GW-level lock replaces per-match `lock_at` for league-format competitions; RLS write policy gates on the gameweek. |
| 3 | Participation | **Opt-in per gameweek.** Submit = you ante and you're in. No submission = not in, no money lost. Matches current Cashford behavior (no pick = not entered). | Pot size varies weekly. Degenerate rules below (§2.5). |
| 4 | Transition | **Same league, new season; ledger carries.** Leagues are permanent; they join competitions. WC 2026 archives read-only per league; one continuous net-dues balance across competitions. Plus a **log-settlement** action to record offline payments. | `competitions` table + `leagues` gain competition participation. Settlement logging spec in §4. |
| 5 | Ties | **Tiebreakers, then split.** Most exact scores → lowest total goal error across the GW → split pot in integer rupees. | Reuses `isExact`/`goalError` primitives from `lib/analytics.ts`. |
| 6 | Postponements | **Drop and settle.** Fixture moved out of a GW is void in that GW; the GW settles when its remaining fixtures finish. The fixture becomes freshly predictable in its new GW (FPL blank/double model). | GW fixture list must re-sync from FPL until lock, then freeze (§2.6). |

Scoring (from the group chat, "1 and 3 is best"): **1 point for correct result (W/D/L), 3 points total for exact scoreline** — exact replaces, not stacks on, the result point. Sum across the GW.

## 2. Rulebook v1 (shareable with the group)

1. **Entry.** Each gameweek is a fresh contest. Predict a scoreline for **every fixture** in the gameweek before the deadline to enter — partial entries don't count and stake nothing. You may edit your picks until the deadline. Entry is final once made — there is no
   withdrawal. (Changed 2026-07-27: withdraw removed per Ananth's design review.)
2. **Deadline.** Same as FPL: 90 minutes before the gameweek's first kickoff. Server time decides. No grace period.
3. **Scoring.** Per fixture: exact scoreline = 3 pts; correct result only = 1 pt; else 0. Gameweek score = sum over the gameweek's counted fixtures.
4. **Pot.** Every entrant antes the league stake (captain-set, applies to future gameweeks only). Highest gameweek score takes the pot.
5. **Ties & degenerate weeks.** Tie at top → most exact scores, then lowest total goal error (Σ|Δhome|+|Δaway|), then split in whole rupees (remainder by the existing lowest-user-id rule). 0 entrants → no contest. 1 entrant → void, ante returned. Everyone scores 0 → tiebreakers still pick the closest wrong predictions (consistent with WC closeness rules).
6. **Fixture changes.** The gameweek's fixture list follows FPL until the deadline, then freezes. A fixture postponed out (before or after kickoff time — same rule) is void in that gameweek and predictable again in its new gameweek. Abandoned matches count only the competition's official final result; a full replay voids the original. Blank gameweeks (fewer fixtures) still run; double gameweeks just have more fixtures to predict.
7. **Results & corrections.** A gameweek settles when its last counted fixture is final. A later official score correction triggers a visible re-settlement (reversal + new transfers), never a silent edit.
8. **Season view.** Cumulative points table + gameweek wins are tracked for bragging rights; no season-end money (can be added later as a separate buy-in).

## 3. Sol review — adopted / rejected

Adopted: complete-entry requirement; withdrawal-until-deadline; 1-entrant refund; snapshot-at-lock; same rule for pre/post-kickoff postponement; abandoned/replay rule; visible re-settlement for corrections; stake changes future-only; mid-season joiners enter from next open GW at zero balance; departing members keep balance/history (deactivate, never delete); settlement = exact two-party payments with confirmation (§4).

Rejected/parked:
- **Hide entrant count until lock** (anti pot-sniping). Parked: in 5–15-person friend groups, showing who's in is a social nudge to enter. Accept field-selection as part of the game. *Veto-able.*
- Multiple-accounts policing — invite-only leagues already cover it.
- Pot carry-over on all-zero weeks — tiebreakers resolve it instead.

## 4. Settlement logging (ledger carries across competitions)

- A settlement is a **two-party record**: payer, receiver, exact amount, date, optional note. It adjusts only those two balances — never "zero the league."
- Either party can log it; the **other party confirms**. States: pending → confirmed / disputed. Confirmed records are immutable; mistakes get a visible reversal entry.
- Partial payments allowed; the recorded amount is what was entered, not "whatever clears the debt" (a GW may settle while the screen is open).
- One currency per league (INR today). Archived-competition transfers stay immutable; league-level payments stay open forever.

## 5. Architecture direction (from the codebase map)

The money layer (`transfers`, dues, `simplifyDebts`, analytics) is already competition-agnostic. The WC binding is concentrated and cheap to remove:

1. **`competitions` table** (slug, `espn_slug`/`fpl` source config, format `cup|league`, season, name) — moves the hardcoded `fifa.world` (3 code sites) into data. Backfill `wc2026`.
2. **`fixtures.competition_id`** (nullable → backfill → NOT NULL); widen/replace the `round` CHECK; `gameweeks` table (competition_id, number, deadline_at, status open→locked→settled) with `contests.gameweek_id`.
3. **League↔competition participation** replaces the unfiltered contest fan-out in `app/leagues/new/actions.ts:119` (today: every fixture in the table gets a contest — inserting PL fixtures would silently pollute WC leagues; this must change *before* any PL fixture ingest). Provisioning becomes a recurring job: new GW → contests for every participating league.
4. **Points module**: new pure `lib/gameweek-points.ts` + `lib/settle-gameweek.ts` beside — never inside — the golden-tested per-match engine. Emits standard `transfers` rows; GW results in a sibling table to `contest_results`.
5. **Data source**: FPL API (keyless, verified live for 2026-27) is source of truth for PL fixtures/GWs/deadlines/scores — `bootstrap-static` (events) + `fixtures`. ESPN `eng.1` (verified working) only for odds/insights, matched by home team + kickoff date once, ESPN id stored as `external_id` per the existing pattern. Cron tick gains an FPL sync step; re-fetch fixtures regularly since `event` and `kickoff_time` mutate.
6. **UI rework**: league screen tabs go from Next 24h/Later/Live/Done/Dues (daily cadence) to gameweek-centric (This GW / table / dues). Competition switcher per league; WC tabs incl. `/bracket` become the archived, read-only cup view. `/rules` becomes format-aware.

## 6. Assumed defaults (veto anytime)

- Exact score = 3 pts total (not 4). Entrant list visible pre-lock. Ante = `default_stake_inr` reused as GW stake. Cross-league pick mirroring stays. Split remainder → lowest-user-id rule (existing convention). Late joiner enters next open GW. Blank GWs run the pot regardless of fixture count. FPL deadline followed until our lock executes; never reopen after any fixture starts. Prediction reveal stays post-lock (as today).
